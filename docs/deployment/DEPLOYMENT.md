# Deployment

> **Status:** Designed (not implemented)
> **Last updated:** 2026-09-02

## Overview

Deployment strategy for the bowling machine software system. No deployment infrastructure exists yet.

## Environments

| Environment | Purpose                            | Infrastructure                             |
| ----------- | ---------------------------------- | ------------------------------------------ |
| Development | Local development on developer Mac | Docker Compose (PostgreSQL), local Node.js |
| Staging     | Pre-production testing             | TBD (small VPS or local)                   |
| Production  | Live system                        | TBD (small VPS)                            |

## Development Environment

```
Developer Mac
├── Docker Compose
│   └── PostgreSQL 16
├── apps/api (Node.js, port 4000)
├── apps/web (Next.js, port 3000)
└── apps/esp32-simulator (Node.js, port 5000)
```

Setup steps (future):

```bash
pnpm install
docker compose up -d          # Start PostgreSQL
pnpm db:migrate               # Run migrations
pnpm dev                      # Start all apps
```

No Kubernetes. No container orchestration beyond Docker Compose for local dev.

## Deployment Process (Future)

```
1. Push to main branch
2. GitHub Actions CI passes
3. Build production artifacts
4. Deploy to VPS (SSH + rsync or Docker)
5. Run database migrations
6. Restart services
7. Health check verification
```

Exact deployment mechanism TBD (see [Unresolved Decisions](../architecture/UNRESOLVED_DECISIONS.md)).

## Environment Variables

All configuration via environment variables. See `.env.example` for the full list.

Production-specific:

- `NODE_ENV=production`
- `DATABASE_URL` — production PostgreSQL connection
- `SUPABASE_*` — production Supabase project
- `MACHINE_WS_SECRET` — strong random secret

## Database Migrations

Managed by Drizzle ORM in `packages/database`:

- Migration files generated by `drizzle-kit generate`
- Applied by `drizzle-kit migrate`
- Run automatically on deployment (or manually with confirmation)

## SSL/TLS

- Development: HTTP (local network)
- Production: HTTPS via Caddy (automatic Let's Encrypt) or Nginx + certbot
- WebSocket: WSS in production

## Monitoring (Future)

Minimal monitoring for MVP:

- Health check endpoint (`GET /health`)
- Process manager (systemd or PM2) for auto-restart
- Log files with rotation

Advanced monitoring (Prometheus, Grafana) deferred until needed.
